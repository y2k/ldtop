# Proposal

## Why

После просмотра службы в `ldtop ls` нужно быстро прочитать её вывод, не разыскивая пути вручную. У установленной `local.kofftop-tldr.prepare` launchd уже сообщает общий файл stdout/stderr, поэтому первая итерация может использовать существующие файловые логи.

## What Changes

- Добавить `ldtop log <label>`: последние 200 строк каждого настроенного файла stdout/stderr, один снимок без ожидания новых записей.
- Получать пути из `launchctl print` в текущем контексте по полному label; одинаковый путь читать один раз.
- Различать отсутствие настроенных путей и ошибки получения службы или чтения файлов.
- Дополнить справку и README. Unified Log, поиск собственных логов приложения, настройка логирования и ротация не входят в итерацию.

## Capabilities

### New Capabilities
- `service-logs`: чтение последних строк файлов stdout/stderr выбранной службы launchd.

### Modified Capabilities
- `service-listing`: обновление общего CLI help и уточнение запрета новых команд как ограничения интерфейса `ls`, чтобы разрешить отдельную команду `log`.

## Impact

Затронуты `bin/main.ml`, получение и разбор сведений в `lib/service_listing.ml`, тесты в `test/` и `README.md`. Переиспользуются текущие разрешение launchctl-контекста и запуск процессов без shell; предполагается системный `/usr/bin/tail`, без новых библиотек. Формат и фильтрация `ldtop ls` сохраняются.
