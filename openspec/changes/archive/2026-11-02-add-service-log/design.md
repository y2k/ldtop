# Design

## Context

Мотивация описана в `proposal.md`. CLI в `bin/main.ml` принимает только `ls`. В `lib/service_listing.ml` уже есть `resolve_domain`, разбор верхнего уровня `launchctl print`, `execute` без shell и экранирование диагностик. `collect` фильтрует службы, читает plist и вызывает blame, поэтому для `log` он не подходит. Тесты используют подставляемый runner и отдельную проверку CLI.

На установленной `local.kofftop-tldr.prepare` оба поля `stdout path` и `stderr path` указывают на `/Users/igor/Library/Logs/kofftop-tldr/prepare.log`, даже когда служба не запущена. Дизайн нужен для согласования нового CLI, общего парсера и чтения файлов.

## Goals / Non-Goals

**Goals:** переиспользовать существующую инфраструктуру контекста и процессов; ограничить чтение хвостом файла; сохранить независимость `log` от фильтров и дорогого сбора таблицы.

**Non-Goals:** новая библиотечная архитектура, выбор домена флагом, поиск по сокращённому имени, объединение строк по времени, анализ содержимого логов и хранение собственной истории.

## Decisions

### Источник и подходы

Согласованный источник — пути из загруженной конфигурации `launchctl print`. Чтение plist вместо него может показывать устаревшие настройки, а Unified Log не является сохранённым stdout/stderr. Эти альтернативы не входят в выбранную первую итерацию.

Команда использует полный label и `resolve_domain`, затем один `print <domain>/<label>`. Не вызывает `collect`, `list`, `blame` или plutil. Разбор существующего формата расширяется двумя необязательными полями. Проверки экземпляров records и fixtures входят в задачу изменения парсера. Ошибка структуры ответа для `log` фатальна, а не маскируется как отсутствие логов; прежняя частичная обработка `ls` сохраняется.

### Чтение последних строк

Предлагаемый технический выбор: системный `/usr/bin/tail -n 200` с путём отдельным аргументом, через существующий механизм запуска процессов, без shell. Это проще своего обратного чтения блоками и не требует загрузки всего файла. Перед чтением проверить абсолютный путь, отсутствие NUL и regular-file тип; при необходимости открыть nonblocking и проверить дескриптор, чтобы FIFO не блокировал команду. Символические ссылки на обычные файлы допустимы.

Одинаковые строки путей объединяются; для разных путей порядок stdout, затем stderr. Дедупликация по inode и распознавание разных ссылок на один файл не нужны. Тестовый reader/runner позволяет проверять ошибки независимо от настоящих служб.

### Представление и исходы

Детали по умолчанию для этой итерации: каждый файл получает заголовок `==> stdout: /path <==`, `stderr` либо `stdout/stderr`. Содержимое сохраняется, между секциями добавляется разделитель, если финальная строка не завершена. Имена в заголовках и диагностике экранируются существующим helper.

Нет путей — информационное сообщение и код 0; пустой файл — заголовок без содержимого и код 0. Ошибка одного источника не мешает показать другой, но общий код 1. Ошибка контекста/print — код 1 без попытки искать замену. Ошибка синтаксиса команды — код 2. Эти исходы закреплены в specs.

### Совместимость

`log` не наследует фильтры `ls`: точный label можно запросить независимо от видимости строки. Help дополняется без удаления объяснений таблицы. Delta `service-listing` явно снимает конфликт старой фразы «No commands or flags SHALL be added» с новым отдельным действием.

## Risks / Trade-offs

- Нестабильный диагностический формат launchctl → использовать существующий разбор верхнего уровня и fixtures с неизвестными/вложенными полями; некорректный ответ отличать от отсутствующих путей.
- Ротация или удаление файла во время чтения → сообщать фактическую ошибку; снимок разных файлов не атомарен и не является историей конкретного запуска.
- Огромные отдельные строки → лимит в строках не ограничивает число байтов; не вводить скрытое обрезание, меняющее договорённость о 200 строках.
- Логи могут содержать ANSI-последовательности → содержимое выводится как у tail; экранирование применяется к заголовкам и диагностике.

## Migration Plan

Собрать новую версию и обновить бинарник обычным способом проекта. Конфигурации служб и лог-файлы не изменяются; откат — предыдущий бинарник. Проверка на kofftop_tldr ограничивается чтением, без запуска публикации или перезагрузки агента.
