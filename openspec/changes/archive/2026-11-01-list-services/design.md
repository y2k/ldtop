# Design

## Context

Мотивация описана в `proposal.md`. В проекте есть только `bin/main.ml` с `Arg.parse` и приветствием; `lib/dune` и `test/dune` пока содержат комментарии. Сборка и проверки выполняются через Dune и Makefile. Дизайн фиксирует новую границу между CLI, запуском процесса и тестируемым разбором данных.

## Goals / Non-Goals

**Goals:** отделить разбор и форматирование от системного вызова; обеспечить проверку ошибок без управления настоящими службами.

**Non-Goals:** универсальная библиотека launchd, собственный демон, сторонний CLI-фреймворк, установка пакета или новая система сборки.

## Decisions

### Подходы

Пользователь выбрал разовую команду `ldtop ls` и источник `launchctl list`. Интерактивный экран требует отдельного цикла обновления и не нужен для первого сценария. Чтение `.plist` не заменяет этот источник: оно описывает файлы, а не зарегистрированные службы. Прямой доступ к внутренним API launchd не оправдан для обёртки.

### Получение данных

Вызывать `/bin/launchctl` с аргументом `list` через стандартный модуль Unix без shell. Читать stdout через pipe, stderr наследовать: сообщения остаются видны, отдельный stderr pipe не создаёт риска взаимной блокировки. Закрывать дескрипторы и дожидаться процесса при любых исходах. Таблицу выводить только после успешного завершения процесса и полного разбора.

Использовать текущий контекст запуска без `sudo`, переключения домена или объединения user/gui/system. Это именно набор, доступный обычному `launchctl list` из той же сессии, а не обещание собрать все службы с данным UID.

### Минимальная структура

Добавить один небольшой модуль `lib/service_listing.ml` с разбором, сортировкой, форматированием и получением данных. `bin/main.ml` отвечает за аргументы и сообщения CLI. Подключить библиотеку через существующие Dune-файлы и добавить стандартную зависимость `unix`; внешние пакеты не нужны.

Разбор проверяет заголовок `PID Status Label`, учитывая разделители пробелами/табуляцией, и каждую непустую строку. PID — положительное число или `-`, status — знаковое целое, Label — непустое поле. Неверный формат означает ошибку всего результата. Отсортировать записи через `String.compare` по Label. Заголовки вывода: `Label`, `PID`, `Last exit`; значения отделять читаемыми пробелами, не фиксируя ширины как API.

### Фильтрация перед выводом

После успешного разбора всего ответа, перед сортировкой и выводом, исключать записи с точным регистрозависимым префиксом Label `com.apple.`. Использовать `String.starts_with` и `List.filter` внутри `render`; отдельный модуль, конфигурация и флаг не нужны. Разбор продолжает проверять все строки, включая скрываемые. Если записей не осталось, выводить только заголовок с успешным кодом выхода.

Выбран фиксированный фильтр по префиксу. Альтернатива с `--all` отклонена пользователем; скрытие всех незапущенных служб исключило бы полезные задания по расписанию. Значения `com.apple`, `com.appleother.example`, `org.com.apple.example` и `Com.apple.example` не соответствуют префиксу и остаются видимыми.

### Небольшие решения по умолчанию

Предлагаемые технические значения: успех — exit 0, ошибка получения/разбора — exit 1, ошибка аргументов — exit 2. Без подкоманды показывать usage с exit 2 вместо старого приветствия. Сохранить `--help` и `-help`; алиас `list` не добавлять. Локальный запуск остаётся `make run ARGS=ls` или `dune exec ./bin/main.exe -- ls`; установка команды в PATH вне этого изменения.

### Проверки

Небольшие тесты Dune без внешнего фреймворка: смешанный список и сортировка, отсутствующий PID, отрицательный status, пустой список и повреждённый формат. Для процесса использовать тестовую команду через внутренний параметр функции запуска, без пользовательской настройки пути: проверить ненулевой выход, stderr и отсутствие таблицы при ошибке. CLI проверить на help и неверных аргументах. Затем вручную сравнить успешный `ls` с `launchctl list` в одной сессии.

Для уточнения фильтра добавить проверки смешанного списка, точной границы префикса, сохранения незапущенных сторонних служб и заголовка при полном отсеивании. Повреждённая строка с Apple Label по-прежнему должна приводить к ошибке. CLI должен отклонять `ls --all`. В интеграционном сравнении исключать `com.apple.` из ожидаемого списка и обновить `docs/usage.md`.

## Risks / Trade-offs

- Формат `launchctl list` может измениться → проверять формат и явно сообщать об ошибке вместо частичного списка.
- Контекст launchctl зависит от окружения запуска → документировать текущий контекст; не обещать полный список всех доменов пользователя.
- Последний status не равен здоровью службы → выводить число без классификации здоровья.
- Префикс Label не доказывает происхождение службы → описывать точное правило фильтрации; для полного списка пока использовать `launchctl list`.
- Реальный вывод на этой машине ещё не проверен → перед реализацией сверить заголовок и разделители с `/bin/launchctl list`; не сохранять пользовательские Label в тестовые фикстуры.

## Migration Plan

Миграция данных не нужна. Обновить CLI и Dune, выполнить проверки. Откат — возврат изменений исходников; состояние launchd не меняется.
